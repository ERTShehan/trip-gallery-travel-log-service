# Travel Log Service

## Overview
The **Travel Log Service** manages unstructured memories, notes, and experiences associated with specific trips in the Cloud Trip Gallery. Because travel logs can be highly variable in structure (containing rich text, variable image arrays, and dynamic metadata), this service relies on a NoSQL database.

## Technical Details
* **Technology Stack**: Java 25, Spring Boot, Spring Data MongoDB
* **Database**: MongoDB
* **Default Port**: `8082`
* **Service Registry**: Discovers and registers via Eureka Server.

## Key Responsibilities
* **Log Management**: Provides REST APIs to create, read, update, and delete travel logs.
* **Data Persistence**: Connects to a dedicated MongoDB instance to store documents. 
* **Media Linking**: Stores references to image URLs (generated by the Media Service) within the travel log documents.

## Deployment Context
Deployed on GCP within a PM2-managed instance group. It connects to a secure, private MongoDB Compute Engine VM (`10.10.0.2`), with credentials dynamically injected from GCP Secret Manager at runtime to ensure maximum security.
